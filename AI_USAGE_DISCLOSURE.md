## General Notes

- **Workflow pattern for Phase 3:** Strategic planning and design decisions happen in Claude (browser, Opus). Implementation happens in Claude Code (desktop), always run in plan mode first for review before execution. This two-layer approach provides a human checkpoint between design and implementation.
- **All design decisions are mine.** Claude proposes options with tradeoffs; I choose. Examples: Streamlit vs. alternatives, cache as core requirement, tag re-ingestion vs. Python dict, which artifacts to implement, phased build order, color palette, seed query selection, boolean metadata fields over enumeration workaround.
- **All code is reviewed before committing.** Claude Code operates in plan-then-execute mode with my approval at each step.
- **Debugging is collaborative.** Claude Code proposes fixes; I test, verify, and approve. Examples: PDF font encoding required switching to a Unicode-compatible font and sanitizing special characters from corpus chunks; evidence table validation logic was updated to preserve gap identification rows that the prompt was correctly generating; API timeout for artifact generation was increased from 30s to 120s after cache seeding failures, diagnosed through added logging; tag metadata was migrated from semicolon-separated strings to boolean fields after cache seeding revealed that ChromaDB's `$contains` operator silently returned empty results for tags stored as compound strings — this required re-ingestion, cache clearing, and re-seeding.
- **This document is maintained as a running log** and updated at the end of each implementation phase.
